## 实际推导与卡点

- 用户自行提出 `f[u][i]`：其余块已合法封口，包含 u 的未封口块大小为 i。合并儿子时保留边做大小卷积；删边乘儿子大小为 k、k+1 的计数和。
- 关键压缩由提示引入：若子树大小为 s，封口 c 个块、其中 t 个大小为 k+1，则 `s-i=ck+t`、`0≤t≤c`。因此数值下标范围与真正可能有方案的状态数不同；可行大小条件还不保证任意树形都能实现。
- 用户持续追问“支持集少”和“总工作少”的区别、普通树背包能否照用、平移是否只是常数优化，并用“继承单点小儿子，另一侧为大子树”的结构反驳旧助手“任意儿子均可免费继承”的说法。
- 后续讨论改为：大小小于 k 的完整儿子子树不能独立封口，将其吸入偏移；只有一个大小至少 k 的儿子时复用其状态，避免沿长链反复扫描；多个大儿子时再合并。

## 历史复杂度卡点（2026-10-26 补录时）

- 朴素截断树背包讨论到 O(nk)。支持集上界讨论为 `O(min(k,s/k)+1)`；逐点把该上界乘 n 仍可能得到根号级因子，不能据此直接称线性。
- 即使真正分叉仅 O(n/k) 处，也不能忽略一次合并可能枚举两个状态集的乘积。旧对话最后引入势能摊还来支撑线性目标。

## 2026-10-26 至 2026-10-29 续讲与调试

- 助手逐步解释合并树：叶子是原树单点，内部节点表示将两个不相交部分合并；节点大小计原树点数，不计 DP 状态数。用户追问筛去大小小于 k² 的节点后，为何新叶子代表互不相交、各至少 k² 个点的部分。
- 用户联系到普通树上背包的点对计数；曾将“x+y≥k²”也理解为至多 O(n/k²) 次合并，助手用大部分反复吸收大小 k 的部分纠正。该次数界只适用于两侧都至少 k²；跨门槛的合并应按较小侧点数收费。
- 用户实现：双向链表记录稀疏状态，d[u] 作下标偏移，唯一大儿子直接继承链表；大小小于 k 的儿子计入 sz；尾部截去超过 k+1 的状态，再将 f[u][k]+f[u][k+1] 作为大小 0 的封口状态插入链首，供父亲选择切边。
- 实际错误：b 是 int，而 `(b[x+y] += (ll)a[i].w*a[j].w) %= P` 会先将乘加结果转换并写回 int，再执行取模。乘法提升为 long long 不能防止这一步窄化。用户确认改为 long long 后 AC；等价的最小修法是 `b[x+y] = (b[x+y] + (ll)a[i].w*a[j].w) % P`，让取模发生在写回 int 之前。

## 正确性与复杂度依据

- 状态不变量：除包含当前根的未封口块外，其余块均已合法封口；大小 0 表示当前子树整体已合法划分，可在父边处切断。保留父子边对应大小相加，切断对应使用儿子的大小 0 状态。小于 k 的完整子树不能独立封口，只能全部吸入父亲；加偏移后超过 k+1 的未封口块不可能再合法，直接截去。
- 状态配对：真正做卷积的两侧点数 x,y 均至少 k，状态数上界分别为 O(min(k,x/k))、O(min(k,y/k))。设 K=k²，按实际合并树分三类求和：① x,y≥K：保留大小至少 K 的节点后，叶子互不相交，数量至多 n/K，二叉分叉也为 O(n/K)；每次 O(k²)，总 O(n)。② x≤y、x<K≤x+y：单次 O(x)，分给较小侧的 x 个点；这些点由小于 K 的部分进入至少 K 的部分，只能被这样收费一次，总 O(n)。③ x+y<K：在各个互不相交、大小 z<K 的极大部分内部，xy 对应两侧点对，每对只在首次合并时出现；总计 O(z²/k²)=O(z)，再对各部分求和为 O(n)。
- 实际容器开销：只保留 siz≥k 的原树节点形成骨架，设其叶子数为 L；叶子对应互不相交且大小至少 k 的子树，L≤n/k。大小儿子判断仍扫描原树边，总 O(n)；骨架上 `merge` 调用次数为 L-1。因此每次清空 b 及扫描 0..k+1 的 O(k) 开销合计 O(k(L-1))=O(n)，无需改成稀疏清空。
- 链表开销与空间：无大儿子时创建一个初始节点，共 L 个；每个原树点至多插入一次封口节点，共至多 n 个；每次 merge 重建至多 k+2 个节点。因此 tot≤L+n+(k+2)(L-1)≤5n，M=5N 足够。偏移只改 d；每个链表节点在仍被使用的链表中至多从尾部截去一次，旧链表被重建后不再使用，总维护 O(n)。连同原树数组及递归栈，总时间 O(n)、总空间 O(n)。
- 证据：本地以枚举删边核对了 1078 个小例，再以已核对的朴素 DP 检验共 2305 例；“取模后写回 int”的等价修复版全部一致，并通过 3 个 n=10^5 的星形/链形检查。原版的一个确定反例为 n=47、k=1 的重标号链，正确值 814549564，原版为 512559680。上述为本地验证；线上 AC 依据用户反馈，用户最终 long long 版本未完整读取。

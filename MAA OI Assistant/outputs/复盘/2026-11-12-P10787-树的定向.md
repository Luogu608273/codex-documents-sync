# P10787 [NOI 2024] 树的定向

## 贪心为什么可以选 0

用户已有 $O(nm)$ 做法。先处理所有被限制强制的方向，再给编号最小的未定向边选 0。若一条限制从 $a$ 到 $b$ 尚无反向边，且恰好剩一条未定向边，这条边在任何合法补全中都必须逆着路径定向。

需要证明的是，当每条尚未满足的限制都至少剩两条未定向边时，下一位选 0 仍有解。把已定向边连成的各个块缩成点，剩余边构成一棵树。每条尚未满足的限制在缩点树上都经过至少两条边。将缩点树黑白染色，所有边从黑指向白，则任何有向路径至多经过一条缩点树边，所有这些限制同时满足。交换黑白又得到一个合法补全，恰好把每条剩余边都反向。因此可以选取让当前位为 0 的那一个补全。原先已满足的限制始终有已定向的反向边截断。

## 怎样找到刚被触发的限制

用户在提示后给出倍增段的三类状态：剩 0 条、1 条、至少 2 条未定向边。每段的类别至多变化两次。把一条限制的路径在 LCA 两侧拆成互不相交的倍增段，让每段保存引用它的限制编号。设 $c_B$ 为段 $B$ 内未定向边数，对限制 $i$ 维护 $s_i=\sum_B\min(c_B,2)$。段的类别下降时沿引用表扣减计数，$s_i$ 降到 1 时入队，初始为 1 的限制也入队。

出队时复查 $s_i=1$。用户给出的方向判据是：$a$ 到 LCA 一侧已有向下边，或 $b$ 到 LCA 一侧已有向上边，则限制已满足。否则将唯一剩余边逆着 $a$ 到 $b$ 的路径定向。贴出的代码用 `fl` 保存这条边的编号，合并查询结果时即可取出。

段间依赖共 $O(n\log n)$ 条，段到限制的引用共 $O(m\log n)$ 条。每条依赖只传递常数次状态变化，每条限制至多触发一次 $O(\log n)$ 的方向查询，故总时间和空间均为 $O((n+m)\log n)$。

## 实现中的常数

方向查询只在 $s_i=1$ 时执行，此时被查询的每段都至多剩一条边。一个段第一次降到剩一条时，两个半段已经分别剩零条和一条，此时合并就能得到准确的方向标记。因此 `update` 可以在 `old.fl == cur.fl` 时直接返回。另两项讨论过的优化是直接计算同起点的父段，以及初始登记限制时按段长累加 1 或 2。最终 AC 代码和评测耗时未提供，实际采用了哪些优化未确认。

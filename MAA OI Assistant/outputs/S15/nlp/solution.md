# U2247 不自然语言处理（nlp）

## 题意与范围

长度为 n 的整数序列，有 m 条编号为 1～m 的规则 `(x,y,z)`。每次在能匹配某个相邻位置的规则中选编号最小者，再在它的匹配位置中选最靠左者，将相邻的 x、y 合并为 z。重复直到无法合并，输出最终长度和序列。

1≤n,m≤10^6，所有 token 值在 [1,n+m]。时间 2 秒、空间 512 MiB，文件输入输出为 `nlp.in`、`nlp.out`。

## 标准解法

使用双向链表维护当前序列，用小根堆维护所有候选合并。堆的排序关键字为 `(规则编号, 左端节点编号)`。

### 1. 相同左部只保留编号最小的规则

同一对 `(x,y)` 可能出现多次。若编号 j 的规则可用，那么左部相同且编号更小的规则也一定可用，故 j 永远不会被选中。只需要记录每对 `(x,y)` 对应的最小规则编号。

将 `(x,y)` 编码为一个 64 位整数：

```text
key(x,y) = (uint64_t(x) << 32) | uint32_t(y)
```

按 `(key,规则编号)` 排序后去重。查询某对相邻值对应的规则时，在排序数组中二分。这个实现不依赖哈希表的平均复杂度。

### 2. 链表节点编号始终代表相对位置

初始节点编号就是原序列下标 1～n。将节点 p 和其后继 q 合并时，把新值放在 p，删除 q。

每个存活节点代表原序列的一个连续块，其编号为该块最左端原下标；这些块一直按原序列顺序排列。因此，在存活节点之间比较原编号，等价于比较当前序列位置。无需维护删除后的动态排名。

### 3. 候选事件与版本号

堆元素保存：规则编号 j、左端节点 p、p 的版本号、p 当时后继的版本号。

节点每次作为左端参与合并，都修改值和后继，同时令版本号加一。堆顶事件满足以下条件时才有效：

- 左端节点仍存活，并且仍有后继；
- 左端版本号没有变化；
- 当前后继的版本号与事件记录一致。

若左端的后继已经改变，左端必然参与过一次合并，其版本号已改变。因此只记录后继版本、不额外保存后继编号，也不会误认一个新的相邻对。版本递增至多 n-1 次，int 足够。

无效事件弹出丢弃。有效事件执行合并后，只重新检查两个位置：新节点 p 的前驱与 p，以及 p 与其新后继。其余相邻对完全没有变化。

## 正确性证明

保持不变量：每个当前可合并的相邻对，都至少有一个有效事件在堆中。

初始检查所有 n-1 对相邻节点，不变量成立。一次合并仅影响被合并节点周围的相邻关系。旧事件失效，由版本检查排除；合并后把两个可能新形成的相邻对加入堆。其他相邻对的事件保持有效，所以不变量被保持。

删除无效堆顶后，堆顶是所有有效事件中字典序最小者。规则编号优先保证先选最小规则，节点编号优先保证在该规则下选择当前最左位置。因此每次合并都与题目规定一致。

每次合并使序列长度减少 1，故最多合并 n-1 次。堆空时根据不变量不存在可合并相邻对，所以输出正是题目要求的终态。

## 复杂度

规则排序 O(m log(m+1))。最初检查 n-1 对，每次合并最多检查两对，总共不到 3n 次二分和插堆。所有有效、无效事件都只会被弹出一次。

总时间：

\[
O\bigl(m\log(m+1)+n\log(m+1)+n\log(n+1)\bigr).
\]

总空间 O(n+m)。代码中规则、链表和状态使用全局数组；堆至多存入 O(n) 个事件，远低于 512 MiB。

## 部分分

对应程序：`partial_scan.cpp`，根据 m 是否为 1 分支。

### 普通小数据：每轮扫描全部相邻对

规则排序但不去重。每轮扫描全部相邻位置，二分得到该对的最小规则编号，选择全局最小编号；编号相等时保留先扫描到的位置。数组直接删除右侧元素。

最多 n-1 轮，每轮 O(n log(m+1)) 查询和 O(n) 移动，时间 O(m log(m+1)+n² log(m+1))，空间 O(n+m)。覆盖题面测试点 1～4（n,m≤1000）。

### 单规则：栈模拟

从左向右读入 token，压入栈。只要栈顶两项匹配唯一规则，就合并并继续检查栈顶。

归纳地，在压入新 token 前，栈代表已读前缀的终态，其中没有可合并的相邻对。压入 token 后只有最右边界可能出现匹配；合并后也只有该边界向左移动。因此栈每次执行的就是当前已读前缀最左的可合并位置。未读 token 位于这些位置右侧，不会改变优先级，故在线处理与完整序列处理相同。

每个 token 入栈一次、每次合并令栈长减少 1，时间 O(n)，空间 O(n)。覆盖测试点 5、6。程序对其他数据仍使用正确的小数据算法，但不能保证大数据时限。

| 程序 | 目标测试点 | 限制 |
|---|---|---|
| `partial_scan.cpp` | 1～6 | m=1 时线性，否则平方级扫描 |
| `std.cpp` | 全部 | 排序、链表、事件堆 |

题面没有给出各点权重，不标注未经核实的精确分数。

## 实现注意

- 合并后新产生的规则编号可能更小，必须立刻参与全局比较，不能按规则编号单向扫一遍。
- token 值可能相同，也可能合并后回到原值；不能只比较值判断事件是否过期，版本号仍然必要。
- 不要把相同左部的规则任意覆盖，必须保留编号最小者。
- 堆中保存原节点编号，无需更新所有右侧位置。

## 验证与使用

本地用独立的“先枚举规则、再从左扫描位置”暴力，比较了 1760 组小数据，包含重复规则、相同 token、回到原值、相邻重叠和单规则等情况。题面两组原样例均已另行运行并核对。

大数据检查包括 n=m=10^6：重复规则全部合并，以及逆序输入的互异规则全部合并。具体耗时见根目录 `verification.md`。这些测试不代替上述证明，也不代表官方 AC。

默认读取 `nlp.in`、写入 `nlp.out`；标准输入输出编译命令：

```text
g++ -std=c++17 -O2 -DLOCAL std.cpp -o nlp
```

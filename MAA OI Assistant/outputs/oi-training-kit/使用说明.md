# 信息学训练配置包

编译器路径已固定为 `C:\TDM-GCC-64\bin\g++.exe`，版本 10.3.0；GDB 路径为 `C:\TDM-GCC-64\bin\gdb.exe`，版本 10.2。文件均先存放在此配置包中，尚未安装到你真正的训练文件夹。

## 一、把文件放在哪里

下表中的“训练根目录”指你实际保存训练题目和代码的文件夹，不是 `C:\TDM-GCC-64`。

| 配置包内文件 | 训练根目录中的目标位置 | 操作 |
| --- | --- | --- |
| `项目规则补充.md` | `AGENTS.md` | 已有文件时备份并追加内容，不替换原规则；没有时另存为这个名称 |
| `skill/oi-training/` 整个文件夹 | `.agents/skills/oi-training/` | 创建两层目录后复制整个文件夹 |
| `records/训练档案.md` | `outputs/训练档案.md` | 复制；已有档案时合并 |
| `records/训练记录.md` | `outputs/训练记录.md` | 复制；已有记录时保留原记录，不覆盖 |
| `records/模板/` | `outputs/模板/` | 复制两个 Markdown 模板 |
| `templates/main.cpp` | `templates/main.cpp` | 复制代码模板；做题时另存到题目目录 |
| `tools/stress.cpp`、`tools/stress.exe` | `tools/` | 源码与可执行文件一起复制 |
| `examples/` | `examples/` | 可选，用于确认对拍工具能运行 |
| `editor/tasks.json` | `.vscode/tasks.json` | 仅使用 VS Code 时需要；已有配置则合并 `tasks` 数组 |
| `editor/launch.json` | `.vscode/launch.json` | 仅使用 VS Code 时需要；已有配置则合并 `configurations` 数组 |

使用资源管理器重命名时开启“显示文件扩展名”，避免得到 `AGENTS.md.txt` 或 `.gitignore.txt`。现有文件需合并时，先自行复制一份备份。

## 二、启用训练 skill

用 Codex 打开训练根目录，在新聊天中检查技能列表是否出现 `oi-training`。也可以输入 `$oi-training` 要求它提供一次训练提示或复盘。如果没有出现，重新打开该项目或重启 Codex，并检查最终路径是否正好为 `.agents/skills/oi-training/SKILL.md`。

Skill 文件格式会进行基础检查。官方 `quick_validate.py` 需要 Python 的 PyYAML，本机已检查的 Python 环境没有该依赖，因此官方脚本暂未运行；这不代表 skill 已在你的目标项目中启用。官方校验是可选的进一步验证，如希望执行，可在装有 PyYAML 的 Python 中运行：

```powershell
python "C:\Users\605\.codex\skills\.system\skill-creator\scripts\quick_validate.py" ".agents\skills\oi-training"
```

日常可以这样使用：

- “这道题我推到了……，只给一个提示。”
- “复盘这道题，检查我推导在哪一步断了。”
- “记录这次训练：题号……，用时……，接受了一个提示。”
- “安排独立重做，暂时不要透露旧题解。”

训练记录目前为空；不会把本次工具验证当成你完成了训练题。

## 三、编译与调试

### 使用任何编辑器

在训练根目录打开 PowerShell。先创建用于中间文件的 `work` 文件夹，然后执行以下命令。将 `你的代码.cpp` 改为实际源码路径：

```powershell
New-Item -ItemType Directory -Path .\work -Force | Out-Null
& 'C:\TDM-GCC-64\bin\g++.exe' -std=c++17 -Og -g -Wall -Wextra -D_GLIBCXX_ASSERTIONS '.\你的代码.cpp' -o '.\work\main.exe'
& '.\work\main.exe'
```

优化编译：

```powershell
& 'C:\TDM-GCC-64\bin\g++.exe' -std=c++17 -O2 -Wall -Wextra '.\你的代码.cpp' -o '.\work\main.exe'
```

需要断点调试时，用调试编译生成的程序：

```powershell
& 'C:\TDM-GCC-64\bin\gdb.exe' '.\work\main.exe'
```

GDB 中常用命令：`break solve` 设置断点，`run` 启动，`next` 单步，`print 变量名` 查看变量，`continue` 继续，`quit` 退出。若运行需要输入，可以手动输入；也可在 GDB 中使用 `run < 输入文件路径`。

`-D_GLIBCXX_ASSERTIONS` 只启用部分标准库断言，不检查所有原生数组越界，也不能代替 Sanitizer。本包没有配置 ASan/UBSan，因为尚未核实此 TDM-GCC 发行版的支持情况；无需为本包更换编译器。

### 使用 VS Code（可选）

安装或启用 Microsoft 的 C/C++ 扩展（标识符 `ms-vscode.cpptools`），并按第一节放置两份配置。打开需要运行的 `.cpp` 文件，`Ctrl+Shift+B` 执行调试编译，`F5` 通过 GDB 调试。优化编译可在“终端 → 运行生成任务”选择 `OI: release`。

这些配置在源码旁生成同名 `.exe`，会覆盖同名编译产物。VS Code 扩展及其交互界面尚未在本机验证；本包只验证底层编译器和工具。

## 四、对拍

工具用于 Windows 普通非交互题，比较以空白分隔的输出 token，忽略空格及换行差异。多解构造题、浮点误差题等需要专用 checker，此工具不适用。待测程序和暴力程序均从标准输入读数据、向标准输出写答案，不能使用题目文件重定向。

先编译三个程序。数据生成器 `gen` 接收一个命令行随机种子；同一生成器在相同环境使用同一种子应生成相同输入。包内求和示例只用于验证工具连接，实际题目必须换成对应的生成器和可信暴力。

在训练根目录运行示例：

```powershell
New-Item -ItemType Directory -Path .\work -Force | Out-Null
& 'C:\TDM-GCC-64\bin\g++.exe' -std=c++17 -O2 '.\examples\sol.cpp' -o '.\work\sol.exe'
& 'C:\TDM-GCC-64\bin\g++.exe' -std=c++17 -O2 '.\examples\brute.cpp' -o '.\work\brute.exe'
& 'C:\TDM-GCC-64\bin\g++.exe' -std=c++17 -O2 '.\examples\gen.cpp' -o '.\work\gen.exe'
& '.\tools\stress.exe' '.\work\sol.exe' '.\work\brute.exe' '.\work\gen.exe' 100 1 2000
```

最后三个参数依次是轮数、起始随机种子、每个进程的超时时间（毫秒）。每轮种子加一。任何编译命令失败都先停止，不继续运行旧的可执行文件。

工具把本次运行放到 `work/stress/进程号-时间编号/`，每次运行建立新目录。出现不一致、超时或程序异常退出时立即停止，保留 `case.in`、`sol.out`、`brute.out`、各程序的 `.err` 及 `case.txt`。`case.txt` 记录本轮种子、程序路径和状态；并非每次停止都会生成全部文件，应先看是哪一步失败。全部通过时只保留最后一轮。

复现时使用相同三个可执行文件，将轮数设为 1，起始种子改成 `case.txt` 中的值。请保留或备份原可执行文件/源代码版本，以免之后修改导致无法复现。对拍通过只能说明这些测试未发现差异，不能证明算法正确。

重新编译对拍工具的命令如下；`-municode` 用于 Windows 宽字符命令行入口，不能省略：

```powershell
& 'C:\TDM-GCC-64\bin\g++.exe' -std=c++17 -O2 -Wall -Wextra -municode '.\tools\stress.cpp' -o '.\tools\stress.exe'
```

单进程超时用于本地辅助检查，不等同于评测机计时。工具只管理直接启动的三个程序；请勿让它们再启动子进程。

## 五、日常流程与 Git

每题：独立尝试 → 写下推导与卡点 → 获取一个提示 → 继续推导 → 实现验证 → 简短复盘 → 隔几天独立重做。周复盘依据实际卡点调整训练，模拟赛时关闭提示。

有现成 Git 仓库就直接使用；没有时可在训练根目录执行 `git init -b main`。本包没有创建仓库、提交或远程连接。首次提交若提示缺少用户名和邮箱，用你自己的信息在该仓库中设置：

```powershell
git config user.name '你的名字'
git config user.email '你自己的邮箱'
```

保存关键源码、记录和失败输入即可，不需要每次编译都提交。`work/` 默认忽略，重要反例应另存到题目目录后提交。

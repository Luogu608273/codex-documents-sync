### 历史助手

这是一道非常经典的组合数据结构题，其核心解法通常被称为“第二分块”（即分块套并查集，配合势能分析）。

代码给出的做法是**离线处理+逐块处理**。下面为你详细拆解这个做法的核心思想以及代码的对应实现。

### **一、 核心思想：势能分析与并查集**

题目的主要操作是：将区间内 \>*x* 的数减去 *x*。 如果暴力减，每次最坏是 *O*(*N*)。但我们发现一个性质：**操作会让区间内的最大值减小，且值域相同的值会合并，合并后就不会再分开**。

对于一个整块，设当前块内最大值为 *mx*，块内整体被减去的标记为 *Tag*（即块内元素的真实值为 内部值 \- Tag）。对于一次修改 *x*：

> 1. **当 2*x*≤*mx*−*Tag* 时（减去的 *x* 较小）**： 此时 \>*x* 的数较多，≤*x* 的数较少。我们与其去暴力修改 \>*x* 的数，不如**把 ≤*x* 的数加上 *x***，然后把整个块的 *Tag* 加上 *x*。  
   * 这样相当于全体减了 *x*，原本 ≤*x* 的数又加回了 *x*（真实值不变），而 \>*x* 的数真实值减了 *x*。  
   * 此时最大值 *mx* 相对最小值缩小了。  
> 2. **当 2*x*\>*mx*−*Tag* 时（减去的 *x* 较大）**： 此时 \>*x* 的数较少。我们可以直接把 \>*x* 的数暴力减去 *x*（即合并到前面的值域里）。  
   * 此时最大值 *mx* 也会缩小到 *x* 左右。

**结论**：无论哪种情况，每次暴力合并的次数都不超过“当前块内最大值的减小量”。每个块的最大值最多是 105，所以每个块在所有修改中的合并总次数不超过 105。均摊下来是非常快的。我们用**并查集**来快速合并相同的值。

### **二、 代码数据结构映射**

为了实现 *O*(1) 的值域合并和查询，代码为每个块维护了一个并查集：

> * pos\[v\]：真实值为 *v*−*Tag* 的集合，在并查集中的根节点编号。  
> * val\[rt\]：并查集根节点 rt 所代表的内部值（真实值需减去 *Tag*）。  
> * fa\[i\]：并查集数组。  
> * sz\[rt\]：根节点 rt 所在的集合大小（即这个块内该值的出现次数），用于快速回答询问。

### **三、 代码逐段解析**

#### **1\. 预处理与离线思想**

`int B = sqrt (n), S = (n - 1) / B + 1;`  
`for (int p = 1 ; p <= S ; p ++) {`  
    `// 逐个块处理`  
`}`

**空间优化**：如果把所有块的 pos 等数组开齐，空间会爆炸（*O*(*N*×*V*)）。因为不同块的操作是独立的，所以代码选择了在最外层枚举**块**，内层枚举**所有询问**。这样只需要开一个块的并查集数组，空间复杂度降为 *O*(*N*\+*V*)。

#### **2\. 块内初始化**

`cnt = R - L + 1;`  
`int mx = 0;`  
`for (int i = L ; i <= R ; i ++) {`  
    `if (! pos[a[i]]) pos[a[i]] = ++ cnt, val[cnt] = a[i];`  
    `fa[i - L + 1] = pos[a[i]]; // i - L + 1 是块内相对下标`  
    `sz[pos[a[i]]] ++;`  
    `mx = max (mx, a[i]);`  
`}`

遍历当前块 \[*L*,*R*\]，建立并查集。把相同的数字归到同一个根节点 pos\[a\[i\]\] 下，并统计 sz 和最大值 mx。

#### **3\. 处理整块修改 (区间包含块)**

`if (md == 1) {`  
    `if (l <= L && r >= R) { // 整块修改`  
        `if (mx - Tag >= 2 * x) {`   
            `// 较小一半合并到较大一半`

这里严格对应了前文的**势能分析**：

> * mx \- Tag \>= 2 \* x：遍历 1…*x*，把内部值 *v* 的并查集挂到 *v*\+*x* 下面，打上 Tag \+= x 标记。  
> * mx \- Tag \>= x（且 \<2*x*）：遍历 *x*\+1…*mx*−*Tag*，把内部值 *v* 的并查集挂到 *v*−*x* 下面。这里不需要动 Tag。 通过这两种操作，块内的值域不断缩紧，直到全部一样。

#### **4\. 处理散块修改 (区间与块部分相交)**

`else if (r >= L && l <= R) {`

    `for (int i = max(L, l) ; i <= min (R, r) ; i ++)`  
        `if (a[i] > x) a[i] -= x;`  

    `// 3. 重新建立该块的并查集`  
    `mx = 0, Tag = 0;`  
    `cnt = R - L + 1;`  
    `// ...重新初始化的代码（和最开始建块完全一样）`

对于散块，并查集无法部分修改。因此做法是“重构”（Flatten）：

> 1. 遍历块内所有元素，通过 fnd() 找到根节点，减去 Tag 还原成真实值，并清空各种数组。  
> 2. 暴力遍历修改区间内的点。  
> 3. 按照初始化的方式重新把这个块的并查集和信息建好。 重构单次复杂度 *O*(*B*)。

#### **5\. 处理查询操作**

`if (x == 0) continue; // 前面已经处理过 x=0 的特殊情况`  
`else if (l <= L && r >= R) ans[i] += (pos[x + Tag] ? sz[pos[x + Tag]] : 0);`  
`else if (r >= L && l <= R)`   
    `for (int j = max(L, l) ; j <= min (R, r) ; j ++)`  
        `if (val[fnd(j - L + 1)] - Tag == x) ans[i] ++;`

> * **整块查询**：直接查真实值 *x* 对应的内部值 *x*\+*Tag* 有没有根节点。如果有，直接加上对应的 sz 即可，复杂度 *O*(1)。  
> * **散块查询**：暴力遍历散块区间，通过 val\[fnd(j \- L \+ 1)\] \- Tag 算出单点的真实值判断是否等于 *x*。

*(注：代码最开头 sum 数组的预处理是为了应对 x=0 的查询。因为此题修改只针对 \>x 的数，所以 0 永远不会变，单独拿出来做前缀和可以避免查询 0 时产生越界或异常)*

#### **6\. 块收尾工作**

`for (int i = L ; i <= R ; i ++) a[i] = val[fnd (i - L + 1)];`  
`for (int i = 1 ; i <= cnt ; i ++) fa[i] = sz[i] = val[i] = 0;`  
`for (int i = L ; i <= R ; i ++) pos[a[i]] = 0;`  
`Tag = 0;`

这一步极为关键。因为是最外层枚举块，当前块的操作全部处理完毕后，**必须将整个块“解压”回原数组 a**，并清空当前块使用的 pos、fa、sz 等数据结构，以免干扰下一个块的处理。由于值域最大为 105，不能用 memset 清空 pos，这里只清空出现过的 a\[i\]，保证了常数。

### 历史助手

实际上，这段代码里的并查集**是有路径压缩**的。

请看这一行代码：

`int fnd (int p) { return !fa[p] ? p : fa[p] = fnd (fa[p]); }`

其中的 fa\[p\] \= fnd (fa\[p\]) 就是标准的**路径压缩**（Path Compression）。当递归向上查找根节点时，它会把路径上的所有节点直接指向根节点，从而让后续的查找达到均摊 *O*(1) 的复杂度。

### **关于这个并查集的两个细节**

> 1. **为什么没有“按秩合并”（Union by Size / Rank）？** 常规并查集为了防止树退化成链，通常会用 sz 或 rank 来决定谁当父节点。但在这道题（第二分块）中，并查集维护的是**数值的映射关系**（例如把数值 *v* 合并到 *v*\+*x* 或 *v*−*x*）。合并的方向是由题目操作严格决定的（小的并到大的，或者大的并到小的），因此不需要通过 rank 来决定父子关系。  
> 2. **这里的 sz 是用来干什么的？** 代码中的 sz 数组并不是用来优化并查集树高的（按秩合并），而是用来**记录该并查集根节点对应的权值在块内出现了多少次**，从而在处理 *md*\=2 的整块查询时，能够直接以 *O*(1) 的复杂度输出答案 (sz\[pos\[x \+ Tag\]\])。

原案：noya2 問題準備：Rice_tawara459

C：問題概要
Alice が A 円、Bob が B 円持っている
商品 i の価格は Ci 円、購入したときの満足度は Alice が Ui、Bob が Vi
二人は商品を左から順に見て、所持金が足りれば必ず購入する
商品の並べ方を選び、二人の満足度の和を最大化する
制約
N ≤ 200, A, B ≤ 120
2 / 7
C：購入結果を固定したときの並べ方
各商品を「二人」 「Alice のみ」 「Bob のみ」 「誰も買わない」に分ける
この順だけ考えればよい
1 二人とも買う商品
2 片方だけが買う商品を、価格の降順に並べたもの
3 二人とも買わない商品
二人とも買う商品は先頭へ、誰も買わない商品は末尾へ移せる
片方だけが買う商品は、交換法により価格の降順にできる
したがって、各商品を誰が買うかを価格の降順に決めればよい
3 / 7
C：二人とも買う商品の合計価格を固定する
二人とも買う商品の合計価格を L とする
それらを先頭に置いた後の所持金は A − L, B − L
商品を価格の降順に見ながら、
dp[r][a][b] = 満足度の和の最大値
を更新する
r：今後「二人とも買う」にする商品の合計価格
a, b：片方だけが買う商品に使える二人の残金
L を一つ固定した計算量は O(N W3). すべての L を試すと
O(N W4) ( W = max(A, B))
となり、(おそらく) 間に合わない。
4 / 7
C：すべての L を一つの DP で試す
遷移は L を直接使わないので、すべての初期状態
dp[L][A − L][B − L] = 0 (0 ≤ L ≤ min(A, B))
を同じ DP に入れられる。
価格 c 、満足度 u, v の商品について、次を試す
扱い 条件 遷移先と加える満足度
無視 常に可能 (r, a, b), 0
二人 r ≥ c (r − c, a, b), u + v
Alice のみ a ≥ c > b (r, a − c, b), u
Bob のみ b ≥ c > a (r, a, b − c), v
5 / 7
C：結論
最後に r = 0 の状態だけを採用する
答え = max
0≤a≤A, 0≤b≤B
dp[0][a][b]
時間計算量 O(N W3) 空間計算量 O(W 3)
Python は少し厳しいかも…？ (Rice_tawara の Python 解は 2sec くらい)
後ろから商品を返品していく形の DP でも O(N W3) で解ける
